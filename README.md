# Customer Churn Prediction

A classification project that predicts which customers are about to leave, using their behaviour and billing data. The model is built with Scikit-learn and judged on precision, recall and ROC-AUC. The part I spent the most time on is the decision threshold: instead of using the default 0.5, I pick it by looking at what a wrong prediction actually costs the business.

---

## Why this matters

Winning back a customer who has already left is a lot harder than keeping one who is still on the fence. If we can flag the risky customers a few weeks early, the retention team can call them or send an offer. But every offer costs money, so the model should not flag everyone either. That trade-off is what this project is about.

## What's in the data

7,000 customers, 12 input columns, about 26% of them churned.

| Group | Columns |
|---|---|
| Account | `tenure_months`, `contract_type`, `plan_type`, `payment_method`, `has_autopay`, `monthly_charges` |
| Behaviour | `logins_last_30d`, `avg_session_minutes`, `feature_usage_score`, `days_since_last_login` |
| Support / billing | `support_tickets_90d`, `late_payments_6m` |
| Target | `churn` (1 = left, 0 = stayed) |

The data is generated by `src/generate_data.py` with a fixed seed, so anyone who clones the repo gets the same file. It has a few missing values on purpose, and the label has noise added so the problem is not too easy. If you want to use a real dataset instead, see "Using your own data" below.

## How it works

1. **Preprocessing** – missing numbers are filled with the median, numeric columns are scaled, categorical columns are one-hot encoded. All of it sits inside one Scikit-learn `Pipeline`, so nothing leaks from the test set.
2. **Model comparison** – Logistic Regression, Random Forest and Gradient Boosting are compared with 5-fold stratified cross-validation on the training set (80% of the data).
3. **Evaluation** – the best model is tested once on the untouched 20% test set.
4. **Threshold tuning** – the threshold is chosen using out-of-fold predictions on the training data only, so the test set is not used for tuning.

## Results

| Model | CV ROC-AUC | Test ROC-AUC | Test PR-AUC |
|---|---|---|---|
| Logistic Regression | 0.807 | 0.791 | 0.574 |
| Random Forest | 0.793 | 0.772 | 0.543 |
| Gradient Boosting | 0.790 | 0.765 | 0.536 |

Logistic Regression came out on top. That is not surprising here since the churn signal in this data is mostly additive, and it is a useful reminder that a simpler model is sometimes the right one.

**Test set, 1,400 customers (367 actual churners):**

| Threshold | Precision | Recall | F1 | Caught churners | Wasted offers | Missed churners | Net benefit |
|---|---|---|---|---|---|---|---|
| 0.50 (default) | 0.47 | 0.75 | 0.57 | 274 | 314 | 93 | 23,460 USD |
| 0.36 (cost-based) | 0.40 | 0.87 | 0.55 | 318 | 470 | 49 | 24,060 USD |

### Reading the confusion matrix

- **True positive** – we flagged a customer who really was going to leave. Offer sent, customer might be saved.
- **False positive** – we flagged someone who would have stayed anyway. The offer money is wasted.
- **False negative** – we missed a customer who then left. This is the expensive one.
- **True negative** – correctly left alone.

Lowering the threshold from 0.50 to 0.36 catches 44 more churners (missed ones drop from 93 to 49) but sends 156 more unnecessary offers. Precision goes down, recall goes up. Whether that is worth it depends on the numbers below.

### Business assumptions

These live at the top of `src/train.py` and are easy to change:

- Keeping one churner is worth **300 USD**
- One retention offer costs **30 USD**
- An offer saves the customer **50%** of the time

So a correctly flagged churner is worth `0.5 × 300 − 30 = 120 USD`, and a wasted offer costs `30 USD`. The threshold with the highest net benefit is chosen. In this run the gain over the default threshold is small (around 2.6%) because the benefit curve is quite flat between 0.3 and 0.5. If a lost customer was worth more, or offers were cheaper, the best threshold would move lower and the gap would grow.

### What drives churn

Permutation importance shows contract type and tenure matter by far the most, followed by feature usage, late payments and support tickets. Month-to-month customers with short tenure are the highest-risk group.

## How to run (Windows)

You need Python 3.9 or newer. Open PowerShell inside the project folder and run:

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

python src/generate_data.py
python src/train.py
python src/predict.py
```

If PowerShell blocks the activate script, run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` once and try again.

On Mac/Linux, activate with `source venv/bin/activate` instead.

## Using your own data

Put your CSV in `data/churn_data.csv` and check three things at the top of `src/train.py`: the `TARGET` column name, the `ID_COL` name, and that the target is 0/1. Everything else (column types, preprocessing) is picked up automatically. For the Kaggle Telco dataset, convert `Churn` from Yes/No to 1/0 and make sure `TotalCharges` is numeric first.

## Limitations

- The data is synthetic, so the exact numbers will not carry over to a real company. The workflow will.
- The cost assumptions are made up and should be replaced with real figures from the business.
- No hyperparameter search was done. The models use sensible defaults, which keeps the comparison simple.
